# Changelog

## 2.6.2 - 2026-11-28

### Fixed
- **연금복권 로그인 아이디가 계속 비던 문제의 실제 원인**: 로그인 폼에는 암호문용 hidden 필드 `#userId` 가 진짜 입력란 `#inpUserId` 바로 앞에 있다. 느린 기기에서 페이지가 조각나 도착하면 hidden 필드를 먼저 잡아 거기에 값을 넣고 있었다(`방식 id=script` 인데 `id=0/9`). hidden 필드를 가리키는 셀렉터를 없애고, 문서 파싱이 끝난 뒤 입력란을 다시 찾으며, hidden 필드에는 입력하지 않는다.
- **비밀번호에 `"`·`\` 가 있으면 계정 설정이 깨지던 문제**: run.sh 가 계정 JSON 을 문자열로 이어 붙이던 방식을 jq 로 교체.
- 입력 실패 진단의 팝업 감지 보강(사이트 알림창 `.popup-wrap`, `role=alertdialog`).

### Changed
- `update_interval` 옵션 제거 — 센서 갱신 주기 3600초 고정.
- MQTT: 아이디를 비워 두면 Mosquitto broker 애드온의 접속 정보를 자동 사용(`services: mqtt:want`). 기본 주소 `mqtt://core-mosquitto:1883`.
- 설정 화면 한국어/영어 설명 추가(`translations/`): MQTT 입력 예시와 Mosquitto 계정 준비 방법.
- zendriver 버전 고정(0.17.1), Supervisor watchdog(`/health`) 추가.
- GitHub Actions: 단위 테스트 + gitleaks 비밀값·사설 IP 검사.

## 2.4.10 - 2026-11-28

### Fixed (연금복권 브라우저 로그인 보강)
- **RSA 공개키 준비 대기**: 로그인 페이지는 열린 뒤 AJAX(`selectRsaModulus.do`)로 공개키를 받는다. 키가 오기 전에 로그인 버튼을 누르면 `rsa.encrypt()` 가 오류로 죽어 폼이 조용히 제출되지 않았다(느린 기기·네트워크에서 "로그인 실패" 발생). 이제 `rsa.n` 이 설정될 때까지 기다리고, 10초 안에 안 되면 `selectRsaModulus()` 를 다시 호출한다.
- **비밀번호 20자 초과 사전 차단**: 웹 로그인 입력란이 `maxlength="20"` 이라 20자를 넘는 비밀번호는 잘려서 연금복권만 로그인에 실패했다(로또는 HTTP 로그인이라 정상). 브라우저를 띄우기 전에 길이를 검사해 원인을 알려 주며, 로그인 시도를 하지 않으므로 실패 횟수(5회 잠금)도 소모하지 않는다.
- **입력값 확인**: 미리 채워진 값을 비운 뒤 입력하고, 입력란에 실제로 들어간 길이가 기대값과 다르면 클릭 전에 중단한다.
- **성공 판정 확대**: `/login` 을 벗어난 경우뿐 아니라 `/login/loginSuccess.do`·`ExpryPswdNoti` 도달도 성공으로 본다. 대기 시간을 20초에서 30초(또는 `nav_timeout`)로 늘렸다.
- **실패 사유 기록**: 로그인 실패 시 현재 URL·서버 오류문구(`errorMessage`)·화면 알림 모달 내용을 오류 메시지와 로그(`[PENSION-BR] 로그인 실패 상세`)에 남긴다.
- 로그인 소요 시간을 성공 로그에 표시. 런타임 버전 문자열을 2.4.10 으로 맞춤.

### Tests

- **로그인 실패 수정**: 비밀번호 사용기간 만료 안내 페이지(`ExpryPswdNoti`)로 리다이렉트될 때 로그인을 실패로 처리하던 문제 수정. 인증 자체는 성공하고 세션도 유효하므로 로그인 성공으로 처리하고, 비밀번호 변경 권고는 경고 로그로 남긴다.
- 런타임 버전 표시 문자열(로그·웹 UI)을 실제 애드온 버전과 일치하도록 정정.

## 2.1.0 - 2026-10-15

### Added
- **모바일 조회 API 클라이언트(`dh_mobile_api.py`)**: 공식 앱이 쓰는 조회 전용 서버(`ma.dhlottery.co.kr`)에 붙는 로그인 불필요 클라이언트. 번호별 누적 통계, 최신 회차 당첨 상세, 회차 이력 조회를 제공.

### Changed
- **통계 엔진 교체**: Hot/Cold·최다출현 번호 분석이 회차마다 개별 요청을 보내던 방식(약 70회 호출)에서 모바일 조회 API 2회 호출로 전환. 조회 속도와 안정성 개선, 동행복권 서버 부담 감소.
- **최다출현 번호**: 기존 "최근 50회" 표본 대신 공식 전체 누적 통계를 사용해 정확도 향상. 해당 센서 표시 문구를 "전체 누적"으로 정정.

### Fixed
- 코드 전반의 깨진 한글 주석·docstring·메시지 정리(로직·변수명·API 파라미터 변경 없음).

## 2.0.8 - 2026-05-07

### Fixed
- **재시도 시 데드락 해결**: `async_get_with_login()` 이 `async with self._lock:` 안에서 자기 자신을 재귀호출하던 구조를 루프로 변경. asyncio.Lock 은 reentrant 가 아니라 같은 태스크가 두 번 acquire 시도 시 영원히 hang. v2.0.7 이전 코드도 동일한 데드락 잠재성을 가졌으나 일부 경로에서만 발현. 이번에 retry 경로를 통합하면서 데드락이 매번 재현되어 노출됨. 한 번의 lock 안에서 `for attempt in range(...)` 루프로 재시도하도록 리팩토링.

## 2.0.7 - 2026-05-07

### Fixed
- **30초 무응답 hang 해결**: `_async_ensure_main_mode_normal()` 에서 aiohttp 응답 body 를 `async with` 로 끝까지 소비해 keep-alive 커넥션이 풀에 정상 반환되도록 수정. body 미소비로 인한 다음 요청 30초 timeout 패턴 제거.
- **재시도 경로 정상화**: `async_get_with_login()` 이 `DhAPIError` 외에 timeout 등 `DhLotteryError` 도 동일하게 잡아 항상 풀 세션 리셋 + 재로그인하도록 변경. 기존 로직은 첫 실패 후 ensure 만 하고 재요청해서 망가진 세션을 재사용하던 문제 해결.
- **로그인 응답 누수 수정**: `async_login()` 의 POST 응답을 `async with` 로 감싸 body 누수 방지.
- 요청 타임아웃 30s → 15s (connect 10s) 로 단축해 실패를 빨리 감지.

### Note
- GitHub 원본 레포가 삭제되어 동행복권 사이트의 mainMode=Y 간소화 페이지 운영으로 인해 발생한 세션 hang 문제를 패치한 로컬 빌드 버전.
